# 童装 3D 展示 iOS App 首版技术方案

## 1. 方案目标

首版采用“固定商品模型绑定 SKU”的实现方式：模型由运营或建模人员提前制作并发布，用户通过首页选择商品或扫描吊牌上的二维码、条形码，打开对应的 3D 与 AR 展示。

首版重点验证以下能力：

- SKU 能稳定匹配到唯一商品。
- GLB 模型能在 iOS App 内流畅加载和交互。
- USDZ 模型能进入系统 AR 预览。
- 弱网、断网、无权限和无效 SKU 均有明确的降级路径。

## 2. 首版技术边界

### 包含

- 固定商品目录及 SKU 映射。
- 二维码、条形码扫描和手动输入 SKU。
- Three.js 3D 商品展示。
- AR Quick Look 现实环境展示。
- 商品收藏、最近浏览和模型缓存。
- 基础错误日志和使用事件记录。

### 暂不包含

- 通过多张照片在 App 内生成 3D 模型。
- 真人虚拟试衣、身体测量和布料模拟。
- 用户账号、支付、订单和复杂商品后台。
- 摄像头画面上传或云端存储。

## 3. 总体架构

```text
┌──────────────────── iOS App / SwiftUI ────────────────────┐
│                                                           │
│  商品首页 ── 商品详情 ── 收藏/最近浏览                     │
│      │           │                                        │
│      │           ├── WKWebView + Three.js ── GLB 模型     │
│      │           └── AR Quick Look ──────── USDZ 模型     │
│      │                                                    │
│  VisionKit 扫码 ── SKU Resolver ── Product Repository     │
│                                       │                   │
│                              Manifest + Asset Cache       │
└───────────────────────────────────────┼───────────────────┘
                                        │
                              静态文件服务 / CDN
                         商品清单、GLB、USDZ、缩略图
```

首版不需要业务服务器。商品清单和模型使用版本化静态文件发布；App 内置一份基础清单和默认示例模型，远程资源下载后保存到本地缓存。

## 4. 客户端模块

### 4.1 App Shell

- 使用 SwiftUI 构建首页、商品详情、收藏和设置。
- 使用 `NavigationStack` 管理页面跳转。
- 统一管理加载、空数据、权限拒绝和错误提示状态。

### 4.2 Product Repository

- 读取内置商品清单，并在网络可用时检查远程版本。
- 按 SKU、商品 ID 或分类查询商品。
- 校验商品字段、模型地址和资源版本。
- 远程清单失败时继续使用最近一次成功缓存或内置清单。

### 4.3 SKU Scanner

- 使用 VisionKit 的 `DataScannerViewController` 识别二维码和条形码。
- 扫描内容只接受定义好的 SKU 格式，例如 `CLOTHE-0001`。
- 扫描成功后交给 SKU Resolver，禁止直接把扫描内容当作任意网络地址打开。
- 不支持扫码的设备提供手动输入入口。

### 4.4 Three.js Viewer

- 使用 `WKWebView` 加载随 App 打包的 Three.js 展示页面。
- 使用 `GLTFLoader` 加载 GLB 模型。
- 支持旋转、缩放、重置视角、自动旋转和材质颜色切换。
- 暴露加载开始、加载成功、加载失败和交互事件给原生层。
- 页面本身不直接访问摄像头，摄像头权限只由原生模块管理。

### 4.5 AR Preview

- 通过 AR Quick Look 加载商品对应的 USDZ 文件。
- 打开前确认文件已下载且可读取。
- AR 不可用时保留普通 3D 查看，并提示设备不支持。

### 4.6 Local Storage

- 使用 `UserDefaults` 保存少量收藏 ID 和设置。
- 最近浏览可使用轻量本地文件或 SwiftData。
- 模型文件使用磁盘缓存，并记录资源版本、大小和最后访问时间。
- 首版不保存摄像头帧、扫码截图或儿童面部信息。

## 5. SKU 与商品数据设计

商品清单建议使用 JSON：

```json
{
  "manifestVersion": 1,
  "products": [
    {
      "id": "coat-001",
      "sku": "CLOTHE-0001",
      "name": "云朵绗缝外套",
      "category": "外套",
      "colors": ["雾霾蓝", "暖杏色"],
      "sizes": ["90", "100", "110", "120", "130"],
      "thumbnail": "assets/coat-001/thumbnail.webp",
      "modelGLB": "assets/coat-001/model.v1.glb",
      "modelUSDZ": "assets/coat-001/model.v1.usdz",
      "assetVersion": 1
    }
  ]
}
```

约束：

- SKU 必须唯一，发布前检查重复值。
- 商品 ID 发布后保持稳定。
- 模型更新时递增 `assetVersion`，避免旧缓存继续生效。
- 清单中的资源只允许来自 App 配置的可信域名。

## 6. 模型资源规范

```text
assets/
└── coat-001/
    ├── thumbnail.webp
    ├── model.v1.glb
    └── model.v1.usdz
```

建议的首版模型约束：

- GLB 和 USDZ 使用相同真实比例、朝向和中心点。
- 模型正面朝向统一，落地点统一放在模型底部中心。
- 单个 GLB 目标控制在 10 MB 左右，复杂模型设置合理的面数和纹理尺寸。
- 纹理优先使用移动端友好的压缩方案，并在目标真机上验证兼容性。
- 每个模型发布前检查破面、黑面、材质丢失、比例错误和加载失败。

具体大小不是硬性限制，应以目标设备上的加载时间、内存和帧率测试结果为准。

## 7. 核心数据流程

### 7.1 扫码打开模型

```text
打开扫一扫
  → 请求摄像头权限
  → 识别二维码或条形码
  → 规范化并校验 SKU
  → 查询 Product Repository
  → 找到商品：打开详情并加载模型
  → 未找到商品：提示重新扫描或手动输入
```

### 7.2 3D 模型加载

```text
进入商品详情
  → 检查 GLB 本地缓存
  → 命中缓存：校验版本后加载
  → 未命中：下载到临时文件
  → 校验完成后原子写入缓存
  → WKWebView 加载模型
  → 失败时显示商品图片和重试按钮
```

### 7.3 AR 模型加载

```text
点击 AR 查看
  → 检查设备能力
  → 获取并校验 USDZ 文件
  → 打开 AR Quick Look
  → 不支持或失败时返回普通 3D 页面
```

## 8. 原生与 Three.js 通信

原生层向 WebView 发送：

- `loadModel(url, productId, assetVersion)`
- `setColor(colorId)`
- `resetCamera()`
- `setAutoRotate(enabled)`

WebView 向原生层回传：

- `viewerReady`
- `modelLoadStarted`
- `modelLoadProgress`
- `modelLoadSucceeded`
- `modelLoadFailed`
- `userInteraction`

消息内容只使用结构化 JSON，并对事件名称、商品 ID 和资源地址进行白名单校验。

## 9. 缓存与离线策略

- App 内置商品缩略图、基础商品清单和至少一个示例模型。
- 下载完成的模型可离线再次打开。
- 缓存达到上限后，优先清理最久未访问且未收藏的模型。
- 清单更新失败不影响已缓存商品的展示。
- 用户可以在设置中查看并清除模型缓存。

## 10. 隐私与安全

- `NSCameraUsageDescription` 明确说明相机只用于扫描商品编码。
- 扫码识别尽量在设备本地完成。
- 不保存、不上传摄像头画面。
- 扫描结果只作为 SKU 查询，不直接执行网址或脚本。
- WebView 禁止任意页面跳转，只加载本地页面和可信模型资源。
- 下载模型时验证 HTTP 状态、文件类型、大小上限和资源版本。

## 11. 测试与验证

### 自动测试

- 商品清单 JSON 解码和必填字段测试。
- SKU 唯一性、格式和查询结果测试。
- 缓存命中、版本失效、空间清理和下载失败测试。
- 原生与 WebView 消息编解码测试。
- 无效资源地址和超大文件拒绝测试。

### 真机验证

- 相机授权、拒绝和系统限制场景。
- 有效 SKU、未知 SKU、重复扫描和手动输入。
- Wi-Fi、移动网络、弱网和离线场景。
- GLB 旋转、缩放、换色和长时间查看的内存表现。
- USDZ 放置、缩放、退出和不支持设备的降级表现。

### 目标指标

- 用户最多三步进入目标商品 3D 页面。
- 正常光线下扫码目标约 2 秒内完成。
- 已缓存模型能够快速打开。
- 主要目标设备交互流畅，不出现持续卡顿或明显内存增长。
- 所有错误场景均有用户可理解的提示和恢复方式。

## 12. 实施阶段

### 阶段一：基础原型

- 建立 SwiftUI 工程和页面导航。
- 接入 1～2 个本地 GLB、USDZ 模型。
- 打通原生层与 Three.js 的模型加载通信。

### 阶段二：完整核心流程

- 接入商品清单、SKU Resolver 和 VisionKit 扫码。
- 完成商品详情、收藏、最近浏览和 AR 入口。
- 加入模型下载、缓存、错误处理和离线降级。

### 阶段三：首版验收

- 准备 6～10 件正式示例商品。
- 完成单元测试、集成测试和目标设备真机测试。
- 优化模型大小、加载速度、内存和交互体验。
- 完成隐私说明、相机权限文案和发布前检查。
